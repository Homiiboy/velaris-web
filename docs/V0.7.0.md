# Velaris V0.7.0 — TV Mode & App Experience

**Status: Complete and validated**

V0.7.0 strengthens Velaris as a living-room and installed-app experience. The release deliberately builds on Jellyfin Web's existing layout detection, spatial focus manager, remote/gamepad command mapping and playback stack rather than creating a second input or playback system.

## Completed scope

- global TV/App Experience controller integrated into the modern Velaris application shell
- live synchronization with the existing `layoutManager.tv` state and layout mode changes
- full 10-foot TV presentation rules for toolbar, primary navigation, action targets and content spacing
- overscan-safe horizontal and bottom padding for TV layouts
- stronger TV focus-visible treatment and larger focus targets
- route-aware TV focus restoration after modern-app navigation
- focus priority for explicit TV targets, current-page controls, selected controls and general focusable content
- protection against stealing focus from active page content or dialogs
- existing Jellyfin remote/gamepad/Tizen/WebOS keyboard mappings retained as the input foundation
- TV-optimized video OSD focus that prioritizes the primary playback action when the OSD opens
- immediate TV-player event registration when playback is already active
- larger Advanced Player panel controls in TV mode
- compact, tablet and desktop viewport classification exposed at the application root
- responsive app-shell adjustments for tablet and compact layouts
- lightweight app-startup entrance transition with reduced-motion support
- non-blocking global offline banner driven by browser connectivity state
- connection-check action that reloads once connectivity is available
- redesigned server-unreachable state with an explicit retry action
- existing server switching and server-mismatch recovery retained
- compatibility-safe focus ancestor traversal for older browser/WebView targets
- regression coverage for TV focus priority, hidden-target filtering, dialog/content focus preservation and viewport classification
- strict zero-warning lint coverage for the new TV/app experience, connection recovery and TV player controller

## TV and remote behavior

Velaris does not introduce a parallel gamepad or remote-control stack. Existing Jellyfin keyboard navigation already maps directional keys, gamepad controls and supported TV-platform keys into the application's spatial navigation commands. V0.7.0 keeps that mechanism intact and focuses on making the Velaris surfaces reliably navigable with it.

After a route change in TV mode, Velaris restores focus only when focus is outside the active main content and outside a dialog. The target order is deterministic: an explicit Velaris TV primary target, the current-page element, an already selected element, then the first usable focusable control. Hidden or disabled targets are ignored.

## 10-foot layout

The TV presentation increases navigation and action sizes, exposes useful navigation icons, adds overscan-safe spacing and gives keyboard/remote focus a strong cyan ring. Existing content cards and list entries receive a restrained focus scale while reduced-motion users keep a non-animated state.

The Advanced Player remains the V0.6 playback surface, but its interactive controls become larger in TV mode. When the video OSD opens and focus is not already inside it, the TV player controller directs focus toward the primary playback control so remote users can act immediately.

## App startup and responsive behavior

The modern app shell now exposes compact, tablet and desktop viewport state at the root and responds to resize events without changing the underlying routing model. A short Velaris startup entrance is applied after mount and is disabled when the operating system requests reduced motion.

This layer is intentionally presentation-oriented: it does not replace the existing PWA manifest, native shell integrations or Jellyfin application bootstrap.

## Offline and server recovery

Browser offline state produces a non-blocking Velaris connectivity banner instead of replacing the current screen. The banner updates from online/offline/focus events and offers a connection check action.

When the Jellyfin-compatible connection layer reports that the server itself is unavailable, the existing connection error page now provides an explicit **Erneut versuchen** action. Multi-server switching and server-mismatch recovery remain available exactly where supported before V0.7.0.

## Compatibility

The TV/app experience continues to depend on the existing Jellyfin-compatible systems for:

- layout and TV-mode detection
- spatial focus movement
- keyboard, remote and gamepad command mapping
- routing and navigation history
- server selection and connection state
- playback and OSD behavior

Validation caught `Element.closest()` as unsupported by the oldest configured Chrome/WebView target. Velaris replaced that usage with simple parent traversal, keeping the new focus helpers compatible with the project's generated-bundle targets.
