## Release Hub

The Release Hub uses media already available through the connected Jellyfin-compatible server. It does not call an external release-calendar service and it does not invent schedule information.

### New this week

Velaris builds the weekly surface from Series/Episode items actually added to matching Series/Anime libraries during the current local calendar week. The model deduplicates repeated items across queries and keeps Anime classification when the same item is visible through overlapping library contexts.

The page exposes:

- total titles new this week
- new-episode count
- detected Season Starts
- filters for All, Series and Anime
- direct navigation to normal media details

### Season Starts

A season premiere is detected only for Episode items where the available metadata identifies episode 1 of a numbered season. The Release Hub does not manufacture missing season numbering.

### 28-day calendar

The calendar includes upcoming Episode items whose real `PremiereDate` falls from today through the bounded 28-day window. Date-only premiere values are normalized to stable UTC calendar days so the visible release date does not shift because of the viewer's timezone.

Items without a usable premiere date are omitted instead of receiving a guessed date. If no upcoming server metadata exists, Velaris shows an explicit empty state.

### Loading and failure behavior

Release data is loaded per matching library with bounded paging instead of a fixed first-page assumption. Loading stops when the relevant date boundary has been crossed or the available result set is exhausted.

Velaris distinguishes:

- successful data
- partial library/query failure or truncation, while preserving already loaded entries
- complete Release Hub query failure
- no matching Series/Anime libraries
- a valid empty upcoming calendar

This keeps failures visible without turning incomplete server data into fake certainty.

## Personal Insights

Insights uses the active Jellyfin profile's existing `UserData`. Velaris does not introduce a second viewing-history database, hidden analytics service or background event tracker.

The Insights model covers watched Movie/Episode items and exposes:

- completed-title total
- completed films
- completed episodes
- known PlayCount total
- rewatches derived from plays beyond the first known play per title
- estimated watch minutes
- titles with a recorded last play in the previous 30 days
- Top Genres ranked by known plays and derived minutes
- Top Series ranked by watched episode count, known plays and derived minutes
- recent items ordered by the stored `LastPlayedDate`

### Watch-time semantics

Jellyfin's item user data provides useful state such as Played, PlayCount, LastPlayedDate and playback position, but it is not a complete event-by-event historical telemetry stream for every past playback session.

For that reason V0.9.0 labels Watch Time as an **estimate**. It is derived from known item runtime × known PlayCount. Velaris does not claim this number is an exact reconstruction of every historical minute watched.

### Profile isolation

Insights follows the currently authenticated Jellyfin user. Switching profiles changes the server-backed user data used for the model, so one profile's viewing state is not deliberately merged into another profile's Insights.

### Large histories

Played Movie/Episode data is loaded with bounded paging and deduplicated by item ID. If an unusually large history reaches the safety bound, Velaris keeps the collected statistics usable but exposes a partial-state warning instead of silently presenting the subset as complete.

## Final consistency and scope audit

The final V0.9 audit intentionally did not add another feature family. It verified that the planned V0.9 product promises are represented by working surfaces and defensive states:

- Release Hub covers new-this-week, new episodes, season starts, Series/Anime filtering and the 28-day calendar
- Insights covers profile-scoped known plays, watched titles, derived watch time, taste signals and recent activity
- both feature families use actual Jellyfin-compatible data instead of bundled fake media or invented history
- navigation exists across the normal desktop and drawer/mobile application surfaces
- critical Release Hub and Insights logic has regression coverage
- both feature families are included in the Velaris validation pipeline
- V0.9 does not replace authentication, permissions, playback, transcoding or media-management behavior

The remaining roadmap work is therefore stabilization work for V1.0.0, not missing V0.9 scope.

## Compatibility

- Jellyfin-compatible server metadata remains the source for Release Hub library items and premiere dates.
- Release Hub does not introduce an external schedule provider or a second media catalog.
- Jellyfin `UserData` remains the source for personal Insights.
- Insights does not introduce a separate viewing-history database or background tracking service.
- Watch Time is explicitly derived and approximate because V0.9 does not have an authoritative event-by-event historical playback ledger.
- Jellyfin user policy remains authoritative for media access and administrative permissions.
- Authentication, playback, seeking, transcoding, media storage and server permissions remain in the established Jellyfin-compatible stack.
- Empty, missing or partial metadata is surfaced defensively rather than replaced with fabricated values.

## Feature Complete

V0.9.0 completes the planned V0.x feature roadmap. The next release phase is **V1.0.0 — First Stable Release**.

V1.0.0 is reserved for cross-feature regression, desktop/mobile/tablet/TV validation, keyboard/remote/accessibility checks, performance profiling, connection and permission edge cases, preference migration/backward compatibility, broader automated regression coverage and removal of release-blocking defects.

No major new feature family should be introduced before the V1.0.0 stabilization target is satisfied.
