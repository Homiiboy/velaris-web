# Velaris V0.4.0 — Discovery, Watchlists & Smart Lists

**Status: Active development**

V0.4.0 adds a dedicated decision-making layer on top of normal library browsing. The first implementation pass focuses on discovering existing media, maintaining personal lists and generating useful Smart Lists from real server metadata and user state.

## Implemented in the first V0.4.0 pass

- dedicated `/discovery` route
- first-class Discovery navigation on desktop and mobile drawer layouts
- server-backed Movie/Series candidate loading with image, genre, date and user-state metadata
- free-text search over titles, original titles and genres
- content-type filter
- genre filter
- watched/unwatched filter
- runtime buckets
- production-year range
- minimum community-rating filter
- “Surprise me” selection from the active filtered result set
- Smart Lists for unseen media, movies up to 90 minutes, highly rated titles and recently added media
- profile-scoped Watchlist
- profile-scoped custom named lists
- direct add/remove actions from Discovery cards
- custom-list creation/deletion
- versioned defensive browser-storage sanitization
- same-session and cross-tab list synchronization
- responsive Velaris Discovery visuals with keyboard-focus and reduced-motion handling
- regression tests covering persistence repair, list membership, compound filtering, Smart Lists and deterministic Surprise Me behavior

## Persistence and compatibility

Watchlist/custom-list state is currently a Velaris profile preference stored in versioned browser storage. It does not rewrite server metadata or media files. The implementation deliberately keeps server authentication, media queries, permissions, playback and transcoding unchanged.

The storage model is defensive: malformed or stale values are repaired instead of preventing Discovery from rendering. Missing media IDs stay harmless and are only resolved when that title is present in the currently loaded library result set.

## Remaining V0.4.0 hardening

- complete CI validation for the new route, logic, tests and style layer
- validate practical behavior with large libraries and empty/partial metadata
- refine Anime/Anime Movie discovery classification where library context can be represented reliably
- decide whether deeper Continue Watching management belongs in this phase without duplicating V0.2.0
- only add list sharing/visibility if it can map safely onto the existing user/server model

V0.4.0 is not complete until the full Velaris validation pipeline is green and the roadmap is updated from In Progress to Complete.
