# Velaris V0.4.0 — Discovery, Watchlists & Smart Lists

**Status: Complete and validated**

V0.4.0 adds a dedicated decision-making layer on top of normal library browsing. Discovery helps users find existing media, maintain personal lists and use useful Smart Lists derived from real server metadata and user state.

## Completed scope

- dedicated `/discovery` route
- first-class Discovery navigation on desktop and mobile drawer layouts
- server-backed Movie/Series candidate loading with image, genre, date and user-state metadata
- paged per-library loading instead of a fixed 500-title result ceiling
- deterministic cross-library deduplication and newest-first ordering
- reliable Anime/Anime Movie classification from library context plus actual media type
- free-text search over titles, original titles and genres
- content-type filter including Movies, Series, Anime and Anime Movies
- genre filter
- watched/unwatched filter
- runtime buckets
- production-year range
- minimum community-rating filter
- “Surprise me” selection from the complete active filtered/list result set
- Smart Lists for unseen media, movies up to 90 minutes, highly rated titles and recently added media
- profile-scoped Watchlist
- profile-scoped custom named lists
- direct add/remove actions from Discovery cards
- custom-list creation/deletion
- Watchlist/custom-list selection as full Discovery result views instead of sidebar previews only
- versioned defensive browser-storage sanitization
- bounds for user-controlled list names, list counts and stored item IDs
- same-session and cross-tab list synchronization
- incremental 60-title result rendering to keep large result sets manageable
- graceful partial-library/truncation warning states while preserving already loaded media
- defensive behavior for missing/invalid runtime, production year, rating and creation-date metadata
- responsive Velaris Discovery visuals with keyboard-focus and reduced-motion handling
- regression tests covering persistence repair, list membership, compound filtering, Smart Lists, deterministic/bounded Surprise Me behavior, Anime classification, paging boundaries, ordering and missing metadata

## Large-library behavior

Discovery now queries relevant user libraries separately in pages of 250 items. It continues until the server-reported total is reached or a short page indicates completion. A defensive upper bound prevents an unexpectedly broken server response from creating an infinite request loop; if that bound is reached, Discovery keeps the loaded media and shows a partial-results warning.

The UI does not render every matching card at once. Results are presented in batches of 60 while filtering, Smart Lists and “Surprise me” continue to operate on the full loaded candidate set. This reduces avoidable DOM work for larger libraries without hiding matching titles.

## Anime and library classification

V0.4.0 reuses Velaris' existing library classification rules. Anime libraries are identified from the user-view/library context, then the actual item type separates Anime series from Anime movies. This avoids relying on title keywords or pretending ordinary animation is necessarily Anime.

Custom/other user libraries are still queried for Movie/Series media. Those items fall back to their real media type so custom library names do not silently exclude valid content from Discovery.

## Persistence and compatibility

Watchlist/custom-list state remains a Velaris profile preference stored in versioned browser storage. It does not rewrite server metadata or media files. Malformed or stale values are repaired instead of preventing Discovery from rendering, and stale media IDs remain harmless until a matching library item is available again.

Playback, authentication, permissions, transcoding and media storage remain controlled by the existing Jellyfin-compatible stack.

## Scope decisions

Deeper Continue Watching mutation controls were not duplicated in Discovery. V0.2.0 Smart Home already owns resume/reset/mark-watched behavior, so V0.4.0 keeps Discovery focused on finding and organizing media rather than creating a second playback-state management path.

Cross-user list sharing was also not added. The current Watchlist/custom-list model is profile/browser scoped and there is no safe server-backed sharing/visibility permission model in this implementation. Adding local-only pseudo-sharing would be misleading, so sharing remains deferred until it can be implemented with explicit server-backed ownership and permissions.
