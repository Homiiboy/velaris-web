# Velaris V0.1.0 — Release Hardening

V0.1.0 is the first stabilization milestone after the V0.0.1–V0.0.9 feature passes. The focus is robustness across the complete viewer-facing flow rather than adding another major visual surface.

## Hardening scope

- Home Spotlight now distinguishes loading from settled empty/error states, preventing a permanent skeleton when no eligible media is available or a request fails.
- Home tab query parameters are constrained to the supported Home/Favorites indexes before any legacy controller is loaded.
- Legacy hash routes are normalized through one shared helper before they enter React Router, preventing malformed relative links if route format changes.
- Desktop navigation, overflow navigation, the mobile drawer, Home discovery and Franchise Spotlight use the same route normalization path.
- Franchise shelves/pages distinguish pending, error and genuinely empty states instead of reporting a transient request state as an empty universe.
- Franchise in-page quick navigation no longer changes the application hash, avoiding interference with application routing.
- Franchise matcher input is normalized defensively so an accidental blank title/studio fragment cannot match every item.
- Public profile-card markup escapes user-controlled display names and IDs and no longer emits the stray quote that could corrupt card markup.
- Public-user discovery falls back to manual sign-in if the public-user request fails, and optional login-branding failures no longer become unhandled promise rejections.
- Profile image upload/delete paths always clear the global loading indicator, report failures, support the current-user fallback ID and restore the existing image after a failed upload.
- The account menu no longer builds a `/userprofile?userId=undefined` route while session data is transiently unavailable.

## Automated regression coverage

V0.1.0 adds focused tests for:

- legacy-to-modern route normalization
- supported Home tab parsing and validation
- Movies / Series / Anime / Anime Movies / Collections detection in English and German
- deterministic core-library ordering
- stable ordering of unrelated custom libraries
- non-mutating library sorting

Existing franchise-engine tests remain in place for empty-hub suppression, localized title matching, curated Arrowverse ordering, manual assignment and duplicate prevention.

## CI hardening

The Velaris workflow now requires:

1. dependency installation with the committed lockfile
2. TypeScript validation
3. repository ESLint
4. a zero-warning strict ESLint pass over Velaris-owned routing, Home, franchise, navigation and login code
5. Stylelint
6. unit tests
7. production build
8. ES5 bundle compatibility validation with the repository's existing `.escheckrc`

The compatibility check runs after the production build and scans the generated JavaScript bundle, complementing source-level TypeScript and lint checks.

## Compatibility boundaries

V0.1.0 does not replace or alter Jellyfin-compatible server APIs, authentication protocols, media decoding, transcoding, playback protocols, permissions or library storage. The release hardening is concentrated in Velaris presentation, routing and failure handling.

The dependency tree still reports the inherited npm audit findings present in the upstream-derived lockfile. V0.1.0 does not claim those third-party dependency findings are resolved; they should be reviewed separately and updated only with compatibility testing.

## Validation limitation

CI can catch compile, lint, unit-test, style and generated-bundle compatibility regressions, but it is not a substitute for a real-browser end-to-end matrix against every Jellyfin server/media/device combination. Manual smoke testing on the target HomeLab remains useful before treating the build as production-stable.
