# Velaris V0.5.0 — Profiles 2.0

**Status: Complete and validated**

V0.5.0 strengthens Velaris as a multi-profile streaming experience. The release adds a global profile startup flow, safer server-authenticated profile switching, profile-scoped presentation settings and server-backed playback-language preferences while retaining Jellyfin-compatible authentication and permissions underneath.

## Completed scope

- global “Who’s watching?” startup gate mounted in the modern Velaris application shell
- automatic discovery of available Jellyfin public users for profile selection
- Jellyfin user avatars in the Velaris profile chooser
- per-profile Velaris accent colors
- profile-scoped Kids Mode UI simplification
- protected-profile prompts using the Jellyfin-compatible authentication path
- explicit profile switching without leaving the current server/app
- session-scoped startup acknowledgement so a deliberate login does not immediately trigger a duplicate chooser
- cache/view reset before another authenticated user becomes active
- safer re-opening of the profile chooser after it has already been dismissed in the same app session
- server-backed preferred audio language
- server-backed preferred subtitle language
- server-backed subtitle mode
- server-backed 4–8 digit profile PIN changes
- current password/PIN input for credential changes without relying on deprecated password-state flags
- versioned profile preference persistence scoped by server and user
- defensive preference sanitization and defaults
- same-session preference update events and cross-tab storage synchronization
- cleanup of profile accent/Kids Mode state when no active user exists
- regression coverage for malformed preferences, server/user scoping, chooser state, chooser reopening and PIN validation

## Profile startup and switching

Profiles 2.0 treats profile selection as a global startup concern instead of a Home-only feature. The chooser is mounted in the main modern app shell, so a restored session that enters another supported route still gets the same profile-selection behavior.

When a user signs in explicitly through the existing login page, Velaris records that user as the selected profile for the current server session. This prevents a second “Who’s watching?” prompt immediately after a deliberate login.

When switching to another profile, Velaris authenticates that user against the connected server, clears the React query cache and legacy view container, updates the active server/user session and then navigates back to Home. The startup-profile marker is stored only in `sessionStorage`, so it remains session-scoped rather than becoming a permanent bypass.

## PIN protection

Velaris does not maintain a separate local PIN database. The profile PIN is set through the existing Jellyfin-compatible user-password API, and protected profile switching is authenticated by the server.

The profile settings surface accepts a new PIN of 4–8 numeric digits. The current password or PIN can be supplied when the server requires it. No PIN value is written into the Velaris profile-preference storage.

## Kids Mode and permissions

Kids Mode is a profile-scoped Velaris presentation preference. It simplifies advanced account/client/admin surfaces where Velaris marks them as non-kid-focused, but it is intentionally not treated as a security boundary.

Actual media visibility and access continue to be controlled by the Jellyfin user policy for the active profile. This keeps parental/media restrictions in the server permission model rather than relying on hide-only browser UI behavior.

## Profile preferences

Velaris profile preferences are versioned and scoped to the combination of server ID and user ID. V0.5.0 currently stores the profile accent and Kids Mode state in this Velaris preference layer.

Smart Home configuration from V0.2.0 already remains profile-scoped to the active Jellyfin user. Audio language, subtitle language and subtitle mode are saved through the server user configuration so the existing playback stack can consume them directly.
