# Velaris V1.0.0 — First Stable Release

**Status: Stable and validated**

V1.0.0 is the first stable Velaris release. Product scope was frozen after V0.9.0 Feature Complete; this release focuses on compatibility, reliability, accessibility, performance and release-blocking defect removal rather than adding another major feature family.

## Stable-release outcomes

### V0.x upgrade and persistence compatibility

- Discovery Watchlist/custom-list persistence migrated from a legacy user-only key to server+user scoping.
- Smart Home ordering/visibility persistence migrated to server+user scoping.
- Franchise Studio state migrated to server+user scoping.
- Existing V0.x values remain readable through backward-compatible legacy fallbacks and migrate on first access when storage is writable.
- Existing server-scoped values take precedence over legacy data after migration.
- Profiles, Control Center and Advanced Player retain their already server+user-scoped preference models.

### Browser-storage hardening

- shared Velaris Local Storage / Session Storage access degrades safely when storage is blocked or unavailable.
- Discovery, Profiles and Control Center preference readers fall back to supported defaults/current in-memory state instead of breaking the app shell.
- profile session-choice handling is safe when session storage is unavailable.
- Advanced Player preference access is routed through the safe storage layer instead of directly assuming `window.localStorage` is usable.

### Navigation, mobile and cross-feature hardening

- mobile drawer open and close behavior is deterministic instead of toggle-based.
- keyboard/arrow input no longer causes accidental drawer state changes.
- route changes clean up drawer state consistently.
- dynamic routes such as `/franchise/:hubId` are matched through route patterns instead of literal path equality.
- drawer routing helpers are isolated from the full app bootstrap for deterministic regression testing.
- primary navigation reports the current destination through `aria-current` instead of relying only on visual color state.

### TV, remote and player hardening

- TV focus restoration does not jump behind active modal overlays.
- `inert`, hidden and `aria-hidden` descendants are excluded from automatic focus targeting.
- TV player focus searches for the first actually focusable OSD action rather than trusting the first selector match.
- focus helper tests are isolated from playback/app initialization.
- older WebView compatibility is retained by avoiding unsupported convenience APIs in Velaris-owned playback helpers.

### Profile and accessibility hardening

- profile selection uses an explicit modal focus cycle.
- initial modal focus is placed programmatically.
- Tab and Shift+Tab remain inside the active profile dialog.
- credential entry receives programmatic focus without JSX `autoFocus`.
- Escape from the credential step returns cleanly to profile selection.
- focusable controls are normalized into DOM order and ignore hidden/inert descendants.
- recovery/offline surfaces use semantic buttons, disabled states and live/alert regions rather than pseudo-button interaction patterns.

### Recovery and connection-loss behavior

- server recovery keeps explicit Retry and server-switching paths.
- unavailable-server actions use real button semantics and preserve disabled/busy behavior.
- offline feedback is non-blocking and announced through appropriate live-region semantics.
- existing Jellyfin connection/authentication mismatch handling remains the underlying recovery mechanism.

### Performance and query behavior

- Release Hub's independent “newly added” and calendar data families can load in parallel per relevant library.
- existing page bounds, deduplication and server-query windows remain intact, so concurrency does not remove load-safety limits.
- no additional background tracker or telemetry database is introduced.

## Regression coverage added during stabilization

V1 expands regression coverage for:

- Discovery legacy migration and cross-server scoping
- Smart Home legacy migration and cross-server scoping
- Franchise Studio legacy migration and cross-server scoping
- unavailable browser storage fallbacks
- dynamic drawer route matching
- responsive drawer open/close behavior
- profile-dialog focus collection and wrapping
- modal/inert TV focus behavior
- TV player focus fallback
- existing Release Hub and Insights bounded/error behavior

Tests that only need a small helper are kept isolated from full Jellyfin application initialization to reduce false failures caused by unrelated globals or bootstrap side effects.

## Security/dependency release gate

V1 adds a shipped-production dependency gate:

```sh
npm audit --omit=dev --omit=optional --audit-level=critical
```

The gate deliberately evaluates dependencies that are shipped as non-dev/non-optional production dependencies. This avoids treating optional native tooling such as the `canvas` path as equivalent to browser runtime code while still blocking Critical findings in the shipped production set.

The general install audit currently reports non-Critical upstream/transitive findings. Several require dependency-range or breaking upgrades, including EPUB/PDF/sanitizer paths, and were not force-upgraded inside the stable release commit because that would introduce materially larger compatibility risk immediately before V1.0.0. They remain dependency-maintenance work for controlled post-1.0 updates.

This does **not** mean the dependency tree is vulnerability-free; it means the V1 stable release gate has no Critical finding in the shipped non-dev/non-optional dependency set at finalization.

## Compatibility guarantees

- no V0.x Velaris list/customization state is intentionally deleted by the V1 migration paths
- legacy preference keys remain readable as migration fallback where needed
- Jellyfin authentication and user policy remain authoritative
- playback, seeking, stream selection, transcoding, SyncPlay and server media handling remain in the established Jellyfin-compatible stack
- Velaris presentation toggles do not weaken server-side access permissions
- server metadata and media files are not rewritten by client preference migrations
- missing browser storage degrades to safe defaults instead of preventing the viewer shell from rendering
- older configured browser/TV WebView targets remain covered by generated-bundle ES compatibility checks
